# 2. CUSTOMER SERVICE POLICY

## 2.1 General Customer Service Principles

Customer support employees and AI assistants must:

* Treat customers respectfully.
* Provide factual information.
* Avoid making unsupported promises.
* Clearly distinguish confirmed information from estimates.
* Protect customer information.
* Escalate issues that require human approval.
* Avoid inventing information that is not available in company systems.

## 2.2 Customer Identification

When a request concerns a specific order, the customer should provide an order ID whenever possible.

The support system may use the order ID to retrieve:

* Order status
* Purchase date
* Approval date
* Estimated delivery date
* Delivery information
* Products associated with the order
* Seller information
* Payment information where authorized

## 2.3 Missing Information

If the requested information cannot be found, the assistant must state that the information is unavailable.

The assistant must not invent:

* Order status
* Delivery dates
* Refund status
* Payment information
* Seller information
* Product specifications
* Company policies

## 2.4 Customer Privacy

Customer information must only be accessed when required to answer an authorized request.

Employees and AI systems must not unnecessarily expose:

* Customer addresses
* Personal identifiers
* Payment information
* Private order history
* Authentication information
* Internal customer records

# 3. ORDER MANAGEMENT POLICY

## 3.1 Order Lifecycle

An order may progress through several states.

Typical order states include:

* pending
* approved
* shipped
* delivered
* canceled
* unavailable

The exact status must always be obtained from the authoritative order database.

## 3.2 Order Status Definitions

### Pending

The order has been created but the order processing or approval process has not been completed.

### Approved

The order has successfully passed the applicable approval process.

### Shipped

The order has been handed over for shipment and shipment information has been recorded.

### Delivered

The order has been recorded as delivered to the customer.

### Canceled

The order has been canceled before completion.

## 3.3 Order Information

Authorized users may request information about:

* Order status
* Purchase timestamp
* Approval timestamp
* Estimated delivery date
* Actual delivery date
* Products
* Seller
* Payment information

The assistant should only return information relevant to the user's request.

# 4. DELIVERY POLICY

## 4.1 Estimated Delivery Date

The estimated delivery date represents the expected delivery date stored in the marketplace system.

An estimated delivery date is not necessarily a guaranteed delivery date.

The assistant must describe an estimated delivery date as an estimate unless an authorized company policy explicitly states otherwise.

## 4.2 Actual Delivery Date

The actual delivery date is based on the delivery timestamp recorded in the company's database.

## 4.3 Late Delivery Definition

For analytics purposes, an order is classified as a late delivery when:

actual delivery date > estimated delivery date

If an order has not yet been delivered, the system should not automatically classify it as a confirmed late delivery unless the applicable analytics definition explicitly supports that classification.

## 4.4 Delivery Questions

When answering delivery-related questions, the assistant should distinguish between:

* Estimated delivery date
* Actual delivery date
* Shipping date
* Current order status

The assistant must not claim that an order will definitely arrive on a particular date unless an authoritative system explicitly confirms it.

# 11. INFORMATION SECURITY POLICY

## 11.1 Database Security

Production databases should use:

* Secure credentials
* Environment variables
* Encrypted connections
* Read-only database users for AI query systems where possible
* Parameterized SQL queries
* Access controls
* Monitoring and logging

## 11.2 SQL Security

The AI database assistant is designed for read-only access.

The following operations are prohibited through the AI query interface:

* INSERT
* UPDATE
* DELETE
* DROP
* ALTER
* TRUNCATE
* CREATE
* GRANT
* REVOKE

The assistant should primarily execute:

SELECT

and approved read-only queries such as WITH queries.

## 11.3 SQL Injection Protection

User input must never be directly concatenated into SQL queries.

Applications should use parameterized queries.

Example:

Correct:

SELECT *
FROM orders
WHERE order_id = :order_id

Incorrect:

SELECT *
FROM orders
WHERE order_id = '{user_input}'

# 12. AI ASSISTANT POLICY

## 12.1 Purpose

The AI assistant helps users interact with company information, marketplace data, and approved business documentation.

The assistant may combine:

* Large language models
* Retrieval-Augmented Generation
* Vector databases
* PostgreSQL
* LangGraph
* Machine-learning models
* Company policy documents

## 12.2 Approved AI Capabilities

The assistant may:

* Answer company-policy questions
* Search company documentation
* Retrieve order information
* Perform database analytics
* Generate read-only SQL
* Explain database results
* Call approved prediction models
* Summarize retrieved information

## 12.3 AI Hallucination Prevention

The assistant should not invent information.

When information cannot be found, it should say:

"The requested information could not be found in the available company records."

The assistant should distinguish:

* Database facts
* Company policy
* Model predictions
* Generated explanations

## 12.4 Database Access

The LLM may generate SQL queries when necessary.

Generated SQL must pass through a SQL safety layer before execution.

The assistant must not directly execute unrestricted LLM-generated SQL.

## 12.5 Prediction Model Usage

Machine-learning predictions are estimates generated by a trained model.

A prediction should not automatically be represented as a guaranteed outcome.

For example:

"The model predicts a high probability of late delivery."

is preferable to:

"This order will definitely be late."

# 15. ANALYTICS DEFINITIONS

## Total Orders

Total number of distinct orders.

SQL concept:

COUNT(DISTINCT order_id)

## Total Items

Total number of order-item records.

## Total Sales

For marketplace analytics, total sales may be calculated as:

product price + freight value

depending on the specific reporting definition.

## Average Order Value

Average sales value per order.

## Late Delivery

An order where:

actual delivery timestamp > estimated delivery timestamp

## Average Delivery Time

Average elapsed time between purchase and customer delivery for eligible delivered orders.

## Seller Order Count

Number of orders associated with a seller.

## Seller Average Delivery Time

Average delivery duration for orders associated with a seller.

# 16. AI DATABASE QUERY POLICY

## 16.1 Query Generation

When a user asks a database-related question, the AI system may generate SQL.

Example question:

"How many delivered orders are there?"

Example SQL:

SELECT COUNT(*) AS total_delivered_orders
FROM orders
WHERE order_status = 'delivered';

## 16.2 Query Validation

Generated SQL must be validated before execution.

The validation system should verify that:

* The query is read-only.
* The query does not contain prohibited SQL operations.
* Referenced tables exist.
* The query is syntactically valid where practical.
* The query does not attempt to expose credentials or system secrets.

## 16.3 Query Execution

After validation, the query may be executed against the authorized database connection.

The result is then passed back to the LLM for explanation.

# 21. FREQUENTLY ASKED QUESTIONS

## Can the AI assistant approve refunds?

No. The AI assistant can explain the refund policy and retrieve authorized refund information, but refund approval requires an appropriate business process or authorized employee.

## Can the AI assistant change an order?

No. The sample AI assistant operates with read-only database access.

## Can the AI assistant delete an order?

No.

## Can the AI assistant execute DELETE queries?

No. DELETE and other write operations are prohibited by the SQL safety layer.

## Can the AI assistant tell me whether an order is late?

Yes, if the required order and delivery information are available.

## How is late delivery defined?

For analytics purposes, an order is late when the recorded customer delivery timestamp is later than the estimated delivery timestamp.

## Is the estimated delivery date guaranteed?

No. It is an estimated date unless an authorized business process explicitly states otherwise.

## Can the AI assistant predict delivery delays?

Yes. If the machine-learning prediction service is available, it can generate a delivery-delay prediction using the model's supported input features.

## Can the AI assistant reveal database credentials?

No.

## Can the AI assistant reveal another customer's order information?

Only when the request is authorized and disclosure is permitted. Otherwise, private customer information must not be disclosed.

## What happens if the database does not contain an answer?

The assistant should clearly state that the information could not be found rather than inventing an answer.

## What happens if company documents disagree with the database?

The assistant should identify the discrepancy and escalate when necessary rather than silently inventing a resolution.
